# SNP2Cluster-Py bioRxiv reproducibility archive

This repository contains the analysis configurations, derived inputs, complete SNP2Cluster-Py run outputs, figure-generation resources, and supplementary material supporting the bioRxiv manuscript:

> **SNP2Cluster-Py: A pathogen-agnostic, context-aware framework for genomic transmission-cluster analysis**

**Authors:** Stanford Kwenda and Alan Christoffels  
**Software version:** SNP2Cluster-Py v1.1.0  
**Software archive:** https://doi.org/10.5281/zenodo.23045861  
**Primary software repository:** https://github.com/stanikae/snp2cluster-py  
**Licence:** See the `LICENSE` file and the licences or access conditions associated with the source datasets.

## Purpose

The archive preserves the exact materials used for the manuscript demonstrations. It is organised around four complete SNP2Cluster-Py analysis runs:

1. *Klebsiella pneumoniae* ST-context Core analysis
2. *K. pneumoniae* Facility + ST Core analysis with Facility-level downstream analysis
3. *Streptococcus pneumoniae* ST-context Core analysis
4. *S. pneumoniae* ST-context Core analysis with Community-level downstream analysis

The original SNP2Cluster-Py run structure has been retained. Each run includes its own configuration, audit records, figures, scientific HTML report, and machine-readable tables. Interactive Core minimum spanning trees and downstream networks are retained in the native self-contained HTML format generated by SNP2Cluster-Py.

## Run-folder contents

Each run folder preserves the output structure generated by SNP2Cluster-Py:

```text
<run_folder>/
├── audit/
├── figures/
├── report/
└── tables/
```

### `audit/`

Contains run-provenance and validation records, including the effective configuration and available environment or manifest information generated for the run.

### `figures/`

Contains static analytical figures and interactive HTML visualisations. Depending on the analysis mode, these may include:

- K-selection diagnostic plots
- annotated Core SNP heatmaps
- temporal transmission scatterplots
- Core minimum spanning trees in self-contained HTML format
- Facility or Community network visualisations in self-contained HTML format

The HTML files can be opened directly in a modern browser. Network and minimum-spanning-tree edges are analytical visualisation relationships and must not be interpreted as confirmed direct or directional transmission events.

### `report/`

Contains the scientific HTML report generated by SNP2Cluster-Py for the run.

### `tables/`

Contains machine-readable CSV outputs. Depending on the analysis mode, these may include:

- `core_snp_clusters.csv`
- `isolate_cluster_assignments.csv`
- K-selection diagnostics
- K-means assignments
- Core MST edge tables
- `transmission_clusters.csv`
- `transmission_context.csv`
- transmission-network node and edge tables

The run-specific CSV files are the authoritative machine-readable results. The supplementary Excel workbook provides manuscript-oriented summaries and does not replace these native outputs.

## Figure 2 reproducibility

The script used to generate Figure 2 is stored at:

```text
manuscript/scripts/generate_figure2_context_comparison.py
```

Example:

```bash
python manuscript/scripts/generate_figure2_context_comparison.py \
  --st-only-core runs/<klebsiella_st_core_run>/tables/core_snp_clusters.csv \
  --facility-st-core runs/<klebsiella_facility_st_run>/tables/core_snp_clusters.csv \
  --metadata data/klebsiella/<metadata_file>.csv \
  --facility-order "Hospital A,Hospital B,Hospital C,Hospital D,Hospital E,Hospital F" \
  --outdir manuscript/figures/main/figure2_outputs
```

Required Python packages:

- pandas
- NumPy
- Matplotlib

The script generates separate PNG, PDF, and SVG panels, a composite Figure 2, and supporting summary CSV files.

## Reproducing the analyses

1. Install SNP2Cluster-Py v1.1.0 from the primary repository or the archived software release.
2. Use the YAML configuration associated with the required run.
3. Confirm that the input paths in the configuration point to the locally available derived inputs.
4. Execute SNP2Cluster-Py using the documented command-line interface.
5. Compare the generated `tables/`, `figures/`, `audit/`, and `report/` outputs with the corresponding archived run folder.

Example invocation:

```bash
snp2cluster run --config <path-to-configuration.yaml>
```

Consult the main SNP2Cluster-Py documentation for the exact command supported by v1.1.0 if the local CLI syntax differs.

## Interpretation boundaries

SNP2Cluster-Py clusters are analytical groupings defined by the configured genomic, epidemiological, and temporal criteria.

- Core SNP cluster membership does not establish epidemiological linkage.
- Facility or Community cluster membership does not prove direct transmission.
- Network and minimum-spanning-tree edges do not establish transmission direction or exclude unsampled intermediates.
- Results depend on the upstream SNP-distance matrix, metadata quality, selected Core context, SNP threshold, and temporal window.
